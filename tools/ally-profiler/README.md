# Ally profiler

Standard-library Python 3.9+ tools for read-only AMD GPU and Linux process/thread telemetry, plus MangoHud CSV analysis. No dependencies to install. The tool never launches a process, attaches a debugger, reads process memory, captures images/shaders, changes settings, or uploads anything. It does not modify Steam shortcuts or Proton prefixes.

## Safety and output

Run from the source checkout. All persistent tool output goes into unique timestamped directories under **`~/nhl-ally-profiles/`**. There is intentionally no arbitrary output-directory option. Keep this dedicated location separate from the game installation; do not place an installation there. Symlinked output bases/parents are rejected. Existing files are never overwritten. Temporary synthetic fixtures use the OS temporary directory and are removed after tests.

Reads are limited to discovered AMD DRM/hwmon nodes, selected `/proc/<pid>/stat`, `/proc/<pid>/status`, task stat/status files, and an explicitly supplied CSV. It does not search for game assets, identify a game automatically, read command lines/environments, or follow descendants. Select the Linux host PID of `nhllegacy.exe`, not Steam, Proton's launcher or wineserver. To observe another process explicitly, repeat `--pid`.

A normal game launch can write saves, caches or logs even though this tool is passive. **Game launch and any configuration changes require separate approval and an agreed test environment.** No gameplay results have been collected with this harness.

## Validate without a game

```bash
cd "$HOME/Projects/nhl-legacy-recomp" || exit 1
PYTHONDONTWRITEBYTECODE=1 python3 tools/ally-profiler/ally_profiler.py self-test
# Equivalent synthetic-only mode:
PYTHONDONTWRITEBYTECODE=1 python3 tools/ally-profiler/ally_profiler.py dry-run
```

These commands run synthetic tests; they do not sample live GPU/process data or write to the home output directory.

## First Desktop Mode session

First obtain approval to launch the game and agree how normal game writes will preserve the playable installation. Use the existing Desktop Mode/Proton path; do not edit a Steam shortcut or prefix. Warm up for five minutes with fixed teams/arena/camera, 720p internal 1×, existing FSR/VSync and 25 W settings. Record actual output size, refresh/caps, AC/battery condition and exact Proton build manually; this harness does not verify them.

In a desktop terminal, these **profiler-only** commands identify a candidate and observe it; they never launch the game:

```bash
cd "$HOME/Projects/nhl-legacy-recomp" || exit 1
ps -eo pid,comm
read -r -p 'Enter the Linux PID of the already-running nhllegacy.exe: ' NHL_PROFILE_PID
python3 tools/ally-profiler/ally_profiler.py collect \
  --session desktop --pid "$NHL_PROFILE_PID" --duration 120 --interval 0.5
```

If there is no approved already-running game, stop after the synthetic test. Verify the PID manually; the script does not know which process is NHL. It prints the unique run directory. Ctrl-C preserves partial JSONL. The first CPU sample has a null rate because a delta needs two samples. Process exit/permission failure is reported in subsequent samples; PID reuse is refused. Short-lived threads may be missed. The collector remains active until its duration ends even if the PID exits.

Use a numeric manual note for run start/end, interruptions and simulation-clock progression. Do not store screenshots. Match-clock speed depends on period-length rules; record normalized uninterrupted progress against a stopwatch, not an assumed one-to-one seconds ratio. Repeat three matched 120-second runs. Menus/replays should be separate runs. The collector includes its own per-sample overhead duration, but its real gameplay overhead remains unmeasured.

### Desktop MangoHud application-layer logging (future approved setup)

Telemetry collection works without MangoHud. It cannot itself produce FPS: a valid frame log is a separate input.

For a later approved one-session launch, enable the application Vulkan MangoHud layer through that launch's environment only. Do not persist it in a shortcut, prefix or global setting. Keep its config/output under `~/nhl-ally-profiles/`. An example configuration to review (not installed or generated by this tool):

```ini
fps
frame_timing
log_interval=0
log_duration=120
output_folder=/ABSOLUTE/HOME/PATH/nhl-ally-profiles/mangohud-desktop
permit_upload=0
```

Replace the absolute path; create the directory before a future run. A temporary environment would supply `MANGOHUD=1` and `MANGOHUD_CONFIGFILE=/absolute/path/to/external.conf` to an approved launcher. This document intentionally supplies no game-launch command or Steam-edit automation. An already-running app cannot be assumed to pick up a newly enabled Vulkan layer. Existing unrelated MangoHud configuration may affect behavior; verify effective settings in the pilot. Do not use upload hotkeys or enable upload settings.

Use a short pilot to check that the log belongs to the application and has approximately one row per rendered/presented interval at `log_interval=0`. Check row count and elapsed duration against the expected cadence; sampled logs must not be relabelled per-frame. Application frame intervals still do not establish physical scanout or simulation updates. Standard MangoHud 0.8.4 logs use `frametime` in milliseconds; this parser requires an explicit unit for that bare header.

Analyze a completed log (no game needed):

```bash
python3 tools/ally-profiler/ally_profiler.py analyze \
  "$HOME/nhl-ally-profiles/mangohud-desktop/REPLACE_WITH_ACTUAL_LOG.csv" \
  --source mangohud-application --frametime-unit ms
```

This first pass reports **sample distributions**, not gameplay FPS. Only after independently validating per-frame sampling:

```bash
python3 tools/ally-profiler/ally_profiler.py analyze \
  "$HOME/nhl-ally-profiles/mangohud-desktop/REPLACE_WITH_ACTUAL_LOG.csv" \
  --source mangohud-application --frametime-unit ms --per-frame
```

Output is printed and saved to a new `summary.json`. Use `--skip-rows N --take-rows N` to select a known gameplay region by data row, excluding the preamble/header. Selection is row-based, not seconds. Preserve original CSVs outside the game; the tool does not copy or modify them.

## Steam Gaming Mode / Gamescope workflow

Validate this separately after Desktop Mode. Use the existing Gaming Mode Gamescope session. **Do not start nested Gamescope, replace the session, change Steam shortcuts, or assume desktop application-layer logs and Gamescope/mangoapp logs measure the same thing.**

Use an already available terminal/access channel to run the same passive collector. Do not enable SSH or install utilities for this task. If no terminal/access channel exists, stop and plan one with approval; the harness does not install a service or background launcher.

```bash
cd "$HOME/Projects/nhl-legacy-recomp" || exit 1
ps -eo pid,comm
read -r -p 'Enter the Linux PID of the already-running nhllegacy.exe: ' NHL_PROFILE_PID
python3 tools/ally-profiler/ally_profiler.py collect \
  --session gaming --pid "$NHL_PROFILE_PID" --duration 120 --interval 0.5
```

The existing session's mangoapp is the supported Gamescope overlay route. Do not inject an additional overlay into the game as an assumed substitute. Establish whether existing mangoapp logging can export per-frame CSV, whether it receives an external config, and whether its frame data refers to application or compositor cadence. A visible HUD does not prove export capability. Session-environment changes/restarts are outside this tool and require approval. If logging cannot be verified, collect telemetry only and report FPS unavailable.

For a verified compatible CSV:

```bash
python3 tools/ally-profiler/ally_profiler.py analyze \
  "$HOME/nhl-ally-profiles/mangoapp-gaming/REPLACE_WITH_ACTUAL_LOG.csv" \
  --source gamescope-mangoapp --frametime-unit ms
```

Add `--per-frame` only after verifying cadence and units for that producer. The parser does not convert arbitrary Gamescope debug traces to MangoHud format. Keep Desktop and Gaming runs labelled separately; record compositor refresh/cap/VRR conditions. No direct numerical comparison is justified until measurement points are understood.

## Output interpretation

`metadata.json` records selected PIDs, session, discovery errors, requested interval/duration and CPU clock-tick scale. `telemetry.jsonl` holds samples with UTC and host monotonic timestamps, elapsed time, collection duration, GPU sensor objects and process/thread objects. Each sensor carries its path, unit, value or error and hwmon label or label error. Zero is retained when actually read; missing/malformed/denied readings stay null. Never add labelled power channels together without knowing the power domains.

GPU discovery selects all DRM cards whose driver resolves to `amdgpu`; no silent first-GPU choice. hwmon temperature (millidegrees), frequency (Hz) and power (microwatts) are converted to C/MHz/W. Active `pp_dpm_sclk`/`pp_dpm_mclk` states are separate fields explicitly labelled **not instantaneous clocks**. Missing hwmon, utilization, clock, power and temperature data remain explicit. Sensor hotplug after initial discovery is not comprehensively handled.

CPU rates use deltas of `utime+stime` divided by elapsed seconds and `SC_CLK_TCK`; **100% means one logical core** and process totals can exceed 100%. Process and thread totals overlap: do not add them. Start ticks guard PID/TID identity; counter resets give null rates. Context-switch fields are cumulative counts, not latency. State is an instantaneous observation. `/proc` reads are not atomic; errors/races are retained. Spin/yield time consumes CPU, so these statistics cannot distinguish useful work from spinning or identify a GPU wait.

CSV handling accepts UTF-8/BOM, optional metadata/version preamble, comma-separated headers with `frametime` or `frametime_ms`, and quoted fields. Bare `frametime` requires `--frametime-unit ms/us/ns/s`; `frametime_ms` explicitly denotes milliseconds. Summary/FPS-only logs, absent data and repeated/duplicate headers fail clearly. Selected malformed/nonpositive/nonfinite rows are counted with line numbers, excluded from distributions, and suppress FPS. No silent FPS-to-frametime substitution occurs.

Percentiles use linear interpolation at `(n-1)*p/100`. With a validated complete per-frame stream, mean FPS is `1000 * frame_count / sum(frame_ms)`; never the mean of instantaneous FPS values. p50/p90/p95/p99 are frame-time percentiles, not “1% low FPS.” Thresholds count frames **strictly greater** than 16.67/33.33/50/100 ms; fraction means fraction of valid rows/frames, not time fraction. Small samples make p99 weak. Without `--per-frame`, the same distributions are explicitly sample statistics and FPS is null.

The importer does not infer CSV `elapsed` units/origin or automatically align frame logs with telemetry. MangoHud 0.8.4 uses elapsed nanoseconds relative to logging start, whereas telemetry uses host monotonic timestamps. Record an independent start marker for coarse correlation; precise synchronization needs future work. No tool output establishes game simulation timing, shader compilation cost, GPU timestamps or synchronization-stall duration.
